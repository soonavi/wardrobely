# avatar-build

Builds `app/assets/avatar/selv-human.glb` — the human body, hair, face detail
and garment meshes the app renders — from MakeHuman's CC0 data set.

```bash
# one-off: fetch the data (CC0) and a Python env
python3 -m venv .venv && .venv/bin/pip install -r tools/avatar-build/requirements.txt
mkdir -p /tmp/mh && cd /tmp/mh
pip download anny==0.6.2 --no-deps && unzip -q anny-0.6.2-py3-none-any.whl
# sha256 of the wheel this asset was built from:
#   bad70bdc2be0dfa9880d60129c3a1339678f08f493184f637dc2825c3e27b8d2

# build (about 30 s)
cd tools/avatar-build
../../.venv/bin/python -m selv_avatar.build \
  --data /tmp/mh/anny/data/mpfb2 \
  --out ../../app/assets/avatar/selv-human.glb

# look at it (needs app/node_modules for three, and esbuild for the runtime bundle)
npx esbuild preview/runtime-entry.ts --bundle --format=esm --external:three --outfile=/tmp/runtime.js
node preview/render.mjs --glb ../../app/assets/avatar/selv-human.glb --out /tmp/shots \
  --config <shots.json> --runtime /tmp/runtime.js
```

After rebuilding, run `cd app && npm test`: `humanAvatar.test.ts` loads the new
file through the real loader and the real runtime and will say if the two no
longer agree.

## Where the body comes from, and its licence

Everything is derived from **MakeHuman / MPFB2 base assets, CC0 1.0 Universal**:
the `hm08` base mesh, the shape targets, the `game_engine` rig and its skin
weights, and the lips mask. They are read from the `data/mpfb2` directory that
ships inside the PyPI `anny` wheel (NAVER LABS Europe), whose
`data/mpfb2/LICENSE.md` is the CC0 text. The build refuses to run if that file
is missing or is not CC0.

Hair, brows, lashes, eyes, beards, glasses, earrings and every garment are
**generated by this code** from that body. No hair or clothing asset is
licensed in.

### The "non-commercial assets" question, answered

`AVATAR_MESH_SHORTLIST.md` left one question open: Anny's README says the free
install "may download non-commercial only assets when needed". Could a build
that only wants the CC0 body end up with non-commercial data?

Not this one, for a reason that can be checked rather than argued:

- The only download code in the package is `anny/paths.py:download_noncommercial_data()`,
  reached only from `get_anny2smplx_data_path()` / `get_anny2smpl_data_path()` —
  the SMPL / SMPL-X topologies.
- **This pipeline never imports or runs `anny`.** It opens files under
  `data/mpfb2` with `open()`, `gzip` and `json`. `find_data_root()` uses
  `importlib.util.find_spec`, which locates a package without importing it.
  PyTorch is not installed, so `anny` could not be imported if something tried.
- The files read are listed in `mhdata.py`: `3dobjs/base.obj`,
  `targets/**/*.target.gz`, `rigs/standard/rig.game_engine.json`,
  `rigs/standard/weights.game_engine.json` (itself marked `"license": "CC0"`,
  which the loader asserts) and `textures/mpfb_lips.jpg`.

So the licence position of the shipped asset is: CC0 inputs, plus original
generated geometry. This is an engineering finding, not legal advice — if
counsel reviews the app, hand them this section.

## What is in the file

A plain glTF 2.0 binary any viewer opens: no extensions (Draco and meshopt
need WebAssembly, which Hermes lacks), no textures (embedded images are a
fragile path on React Native; the avatar is vertex-coloured).

| Node | What | Follows the body by |
|---|---|---|
| `Body` | 14.5k-vertex skinned body, 33 named morph targets | being it |
| `Guide` (hidden) | MakeHuman's clothing/hair/eye helper surfaces | same targets |
| `Sclera_*`, `Iris_*`, `Lashes`, `Brows_<style>` | face detail | surface binding |
| `Hair_<style>` ×11, `Beard_<style>` ×4, `Acc_glasses`, `Acc_earrings` | creator options | surface binding |
| `G_<template>` ×22, `G_base_top`, `G_base_bottom` | garments and the base layer | surface binding |
| 53 joints, one skin | `game_engine` rig, identity rest rotations | joint deltas in the manifest |

`scene.extras.selv` is the manifest: joint order, base measurements, and per
target what it does to stature / BMI / chest / waist / hip and how far it moves
each joint.

**Surface binding** is why adding a garment costs only its triangles: each
vertex stores the three helper vertices it hangs from and barycentric weights;
the runtime (`app/src/features/avatar3d/human/humanRig.ts`) rebuilds it from the
reshaped body. Nothing wearable has morph targets.

**Targets are calibrated to physical units** at build time by measuring the
mesh: 12 cm of stature, 7 BMI points, 9 cm of girth per unit weight — the units
`measurementsToShapeParams` has always used. Gendered axes ship an averaged
target plus an `X_*` cross term, which reproduces MakeHuman's bilinear
(gender × axis) blend exactly in a linear morph system.

## Layout

```
selv_avatar/
  mhdata.py    read the CC0 data (obj, targets, rig, weights)
  macro.py     MakeHuman's macro shape arithmetic
  shapes.py    the target set, calibration, name contract
  rig.py       skeleton + skin weights
  geom.py      normals, closest-point, ray tables, girth
  glb.py       dependency-free glTF writer
  parts.py     Part / Material
  face.py      lashes, brows
  hair.py      eleven procedural hairstyles
  cloth.py     clip / subdivide / smooth / hang
  garments.py  the 22 templates and the base layer
  extras.py    beards, glasses, earrings
  build.py     assemble and write
preview/       headless three.js renderer that runs the app's own runtime
```

## Known limits

- **13 MB.** Most of it is garment and hair geometry. Quantising positions
  would roughly halve it but needs `KHR_mesh_quantization`; left for when size
  matters.
- **Hair is sculpted shells**, not strands or cards. Reads as stylised hair;
  long styles are the weakest.
- **Shoes are a relaxed sock with a sole.** Recognisably footwear, not a
  particular shoe.
- **Loose garments are a hang heuristic, not cloth simulation.** Fine at a
  standing pose; they do not swing or fold.
- **Weights far above MakeHuman's maximum extrapolate.** BMI is clamped at
  roughly 45; the folds are smoothed so it stays a body, but accuracy falls off.
- **Garment photos are not projected onto the mesh.** Garments are tinted
  with their resolved colour.
